# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| latest (main) | Yes |
| older releases | No |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a security vulnerability in Imgo, please report it privately by emailing:

**mdashsharma95@gmail.com**

Include in your report:
- A description of the vulnerability
- Steps to reproduce
- Potential impact
- Any suggested fix (optional)

You will receive a response within **72 hours** acknowledging your report. We will keep you updated as we work on a fix.

---

## What Qualifies as a Security Issue?

- Authentication or authorization bypass
- Remote code execution
- Path traversal in file upload or storage
- Information disclosure (sensitive data in responses or logs)
- Denial of service via image processing (e.g., decompression bomb)
- SSRF or injection vulnerabilities

---

## What to Expect

1. Acknowledgment within 72 hours
2. Confirmation and severity assessment within 7 days
3. A fix will be developed and tested
4. A patched release will be published
5. You will be credited in the release notes (unless you prefer anonymity)

---

## Responsible Disclosure

We ask that you:
- Give us reasonable time to fix the issue before public disclosure
- Do not exploit the vulnerability or access data that is not yours
- Do not perform denial-of-service attacks

We commit to:
- Responding promptly
- Not taking legal action against researchers who follow this policy
- Crediting reporters in release notes

Thank you for helping keep Imgo and its users safe.
